# คู่มือปฏิบัติงานประจำวัน (Daily Operations Runbook) — Lum Him Khue ERP

> สำหรับพนักงานหน้าร้านและเจ้าของร้าน ใช้คู่กับ `INCIDENT_PLAYBOOK.md` (กรณีฉุกเฉิน)
> คำสั่งทางเทคนิค (npm …) เป็นหน้าที่ของเจ้าของ/ผู้ดูแลระบบเท่านั้น

---

## 1. เปิดร้าน (ก่อนเริ่มขาย)

1. เปิดเครื่อง POS / แท็บเล็ต / เครื่องพิมพ์ใบเสร็จ — เช็กกระดาษในเครื่องพิมพ์
2. เข้าสู่ระบบด้วยบัญชีของตัวเอง (ห้ามใช้บัญชีคนอื่น — ทุกการกระทำถูกบันทึกตามชื่อผู้ใช้)
3. **เปิดรอบแคชเชียร์ (Cashier Shift):** POS → รอบแคชเชียร์ → เปิดรอบ → นับเงินทอนตั้งต้น
   ในลิ้นชักแล้วกรอก "เงินตั้งต้น" ให้ตรงกับเงินจริง
   - ⚠️ ถ้าไม่เปิดรอบ ระบบยังรับเงินสดได้ แต่เงินนั้น **จะไม่ถูกนับตอนปิดรอบ** — เปิดรอบทุกครั้ง
4. ทดสอบพิมพ์ 1 ใบ (พิมพ์ QR โต๊ะ หรือใบเสร็จซ้ำจากประวัติ) เพื่อยืนยันว่าเครื่องพิมพ์พร้อม

## 2. เปิดโต๊ะ

1. จัดการโต๊ะ → เลือกโต๊ะว่าง → เปิดโต๊ะ
2. ใส่จำนวนลูกค้าตามประเภท (ผู้ใหญ่ / เด็ก / ฟรี) ให้ตรงกับลูกค้าจริง — ราคาถูกล็อกไว้
   ณ ตอนเปิดโต๊ะ
3. โต๊ะกลุ่ม (นั่งหลายโต๊ะ บิลเดียว): เลือก "โต๊ะเชื่อมโยง" ตอนเปิด — บิลรวมอยู่ที่โต๊ะหลัก
4. ให้ลูกค้าสแกน QR ของโต๊ะเพื่อสั่งอาหาร

## 3. รับออเดอร์ (QR → ครัว)

- ลูกค้าสั่งผ่านมือถือ → ออเดอร์ขึ้นจอครัว (KDS) เองภายในไม่กี่วินาที
- ครัวกด กำลังทำ → เสร็จ → เสิร์ฟแล้ว ตามจริง — ลูกค้าเห็นสถานะบนมือถือ
- ลูกค้าสั่งเพิ่มไม่ได้ถ้ายังมีของค้างเสิร์ฟ — เสิร์ฟแล้วกดให้ครบ

## 4. แก้บิล (เพิ่ม/ลดหัว, ของเพิ่ม)

1. POS → เลือกโต๊ะ → แก้จำนวนหัวหรือของเพิ่ม → **กดบันทึก**
2. ยอดบนการ์ดโต๊ะต้องเปลี่ยนตาม — ถ้าไม่เปลี่ยน รอ 5 วินาที (ระบบรีเฟรชเอง) แล้วดูใหม่
3. หัวที่ **จ่ายแล้ว** (ชำระตามรายการ) ลดไม่ได้ — ระบบจะเตือน ถูกต้องแล้ว อย่าพยายามเลี่ยง

## 5. รับชำระเงิน

1. POS → โต๊ะ → ชำระเงิน
2. เลือกวิธี: QR / เงินสด / ผสม (QR + เงินสด) — เงินสดใส่ยอดรับมา ระบบคำนวณเงินทอน
3. บัญชีรับเงินในบิลเดียวต้องอยู่กลุ่มเดียวกัน (A หรือ B) — ระบบล็อกให้เอง
4. **กดยืนยันครั้งเดียว แล้วรอ** — ถ้าเน็ตช้า ห้ามรัวกด ระบบกันเงินซ้ำให้อยู่แล้ว
   แต่การรอ 2–3 วินาทีดีที่สุด
5. จ่ายสำเร็จ → ใบเสร็จพิมพ์อัตโนมัติ → โต๊ะขึ้น "จ่ายแล้ว" → ไปที่จัดการโต๊ะเพื่อเคลียร์โต๊ะว่าง
6. ใบกำกับภาษี: กรอกชื่อบริษัท/เลขผู้เสียภาษี **ก่อน** กดชำระ — เลขใบกำกับออกอัตโนมัติ ห้ามเขียนเอง

## 6. พิมพ์ใบเสร็จ / พิมพ์ไม่ออก

- พิมพ์ซ้ำได้เสมอ: หน้าจอสำเร็จ → "พิมพ์ซ้ำ" หรือ POS → ประวัติ → เลือกบิล → พิมพ์
- **พิมพ์ไม่ออกแต่จ่ายสำเร็จแล้ว:** เงินเข้าระบบแล้ว ไม่ต้องจ่ายซ้ำ!
  1) เช็กกระดาษ/สายไฟ/ไฟสถานะเครื่องพิมพ์ 2) พิมพ์ซ้ำจากประวัติ
  3) ยังไม่ออก → ดู INCIDENT_PLAYBOOK "printer offline"

## 7. กรณีจ่ายแล้วระบบค้าง / หมุนไม่หยุด

1. **อย่ากดยืนยันซ้ำรัว ๆ และอย่ารีเฟรชทันที**
2. รอ 10 วินาที → เปิด POS → ประวัติ → ดูว่าบิลนี้ **มีรายการชำระแล้วหรือยัง**
3. มีแล้ว → จบ พิมพ์ซ้ำจากประวัติได้เลย
4. ยังไม่มี → กดชำระใหม่ได้อย่างปลอดภัย (ระบบกันเงินซ้ำ — ถ้าเงินเข้าไปแล้วเงียบ ๆ
   ระบบจะแจ้ง "รายการชำระนี้ถูกบันทึกแล้ว" และไม่เก็บซ้ำ)

## 8. ลูกค้าโอนแล้ว แต่บิลยังไม่ปิด

1. เช็กยอดเงินเข้าในแอปธนาคารก่อน (เงินเข้าจริงไหม)
2. เงินเข้าจริง + ประวัติ POS ไม่มีรายการ → กดรับชำระ QR ตามยอดนั้นให้จบในระบบ
3. เงินไม่เข้า → ให้ลูกค้าโอนใหม่ / จ่ายเงินสด — **ห้ามปิดบิลก่อนเงินเข้า**

## 9. ปิดรอบแคชเชียร์

1. นับเงินสดจริงในลิ้นชักทั้งหมด
2. POS → รอบแคชเชียร์ → ปิดรอบ → กรอก "เงินสดนับได้จริง"
3. ระบบเทียบกับยอดคาดหวัง (เงินตั้งต้น + เงินสดที่รับระหว่างรอบ)
   - ยอดต่าง ≠ 0 → **ต้องกรอกเหตุผล** ตามจริง (เช่น ทอนผิด, เก็บเหรียญขาด)
4. เจ้าของ/ผู้จัดการตรวจรอบ (review) ภายหลังได้จากหน้าเดียวกัน

## 10. ปิดร้าน (Daily Close)

1. เคลียร์ทุกโต๊ะ: ไม่มีโต๊ะค้างสถานะ "จ่ายแล้ว" หรือ "มีลูกค้า" ทั้งที่ร้านว่าง
2. ปิดรอบแคชเชียร์ทุกคน (ข้อ 9)
3. เจ้าของ: ดูรายงานรายได้ของวัน (/reports/revenue) เทียบกับเงิน/สลิปจริง
4. สัปดาห์แรกหลัง go-live: เจ้าของรัน `npm run reconcile:payments` ทุกคืน — ต้องผ่าน
5. ปิดเครื่องพิมพ์/อุปกรณ์

## 11. สิ่งที่ห้ามทำ ⛔

- ❌ รัวกดปุ่มยืนยันชำระเงิน หรือรีเฟรชระหว่างชำระ **โดยไม่เช็กประวัติก่อน** (ข้อ 7)
- ❌ ปิดบิลทั้งที่เงินโอนยังไม่เข้า
- ❌ ใช้บัญชีผู้ใช้ของคนอื่น
- ❌ รับเงินสดโดยไม่เปิดรอบแคชเชียร์
- ❌ แก้/ลบรายการชำระเงินเอง — การลบบิลทำได้เฉพาะ **เจ้าของ** และต้องใส่เหตุผลทุกครั้ง
  (ระบบเก็บหลักฐานถาวร)
- ❌ เขียนเลขใบกำกับภาษีเอง หรือออกใบกำกับนอกระบบ
- ❌ (เจ้าของ/ผู้ดูแล) รัน db:push หรือแก้ข้อมูลตรงในฐานข้อมูล production
